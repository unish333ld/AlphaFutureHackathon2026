# Савелий: кнопка и проверка Docker

> Исторический отчёт автора ветки feat/ai-assistant на Windows. Приведённый живой вызов Qwen не перепроверен в новом окружении. После ревью изменены контракт и панель; актуальные проверки и ограничения — [assistant-review.md](assistant-review.md).

Проверено 25.10.2026 на Windows / Docker Desktop, Linux containers. Технологии приложения не менялись: React/Vite, Django/DRF, PostgreSQL, Nginx; локальная OpenAI-совместимая Ollama.

## Причина и исправление

Основной Compose-проект `alphafuturehackathon2026` имел три здоровых контейнера. Backend работал с `AI_ENABLED=true`, но frontend был собран с выключенным `VITE_AI_ASSISTANT_ENABLED`: строки и код виджета отсутствовали в опубликованном JS. При входе клиентом браузерная проверка падала на отсутствии кнопки «Савелий».

Это не ошибка Docker Engine или Nginx. У флагов разные назначения:

- `VITE_AI_ASSISTANT_ENABLED` встраивается Vite в JS при сборке. Значение `false` убирает виджет. Изменение backend environment либо `docker compose restart` не меняет готовый bundle.
- `AI_ENABLED` разрешает серверные ответы. Он не управляет наличием кнопки.
- На странице входа и в кабинете специалиста виджет намеренно не показывается.

В локальных `.env` / `frontend/.env.local` включён frontend-флаг; в корневом `.env` также включён серверный AI. Секреты не перенесены в шаблоны или frontend. Основной frontend пересобран и пересоздан командой:

```sh
docker compose up --build --no-deps -d --wait --wait-timeout 120 frontend
```

Существующие backend и PostgreSQL не пересоздавались; пароли пользователей, данные и volume основной БД не менялись. Основной интерфейс остался на `http://127.0.0.1:8080`, прямой backend — на прежнем `127.0.0.1:18001`.

При проверке обнаружено, что демо-пароль работающего основного backend отличается от текущего корневого `.env`. Для браузерной проверки использован runtime-пароль контейнера без его вывода; пароли пользователей не сбрасывались.

## Проверки

Для изменяющих данные E2E и полного pytest создан отдельный Compose-проект `alfa-saveliy-docker-qa` с собственной PostgreSQL и volume, WEB_PORT=18002, FRONTEND_PORT=18080. Пользовательская демо-база не использовалась для кредитных сценариев.

| Проверка | Результат |

| `docker compose config --quiet` | Успешно |
| `nginx -t` в основном frontend | Успешно |
| `python manage.py check` в Docker | Нет ошибок |
| Полный backend pytest в изолированном Docker-проекте | **370 passed**; 156 предупреждений DeprecationWarning от drf-spectacular / Python 3.14 |
| Frontend `npm run typecheck` | Успешно |
| Frontend `npm run test` | **31 passed** |
| Frontend `npm run build` | Успешно; предупреждение о JS chunk больше 500 kB остаётся |
| Новый `@assistant-ui` в основном frontend до пересборки | Воспроизведено отсутствие кнопки после успешного входа |

| Smoke `ai-disabled.spec.ts`, Chromium, QA frontend пересобран с false | **1 passed**: нет кнопки/панели, вход и просмотр формы/проверки заявки работают; axe-проверки проходят |
| Prettier для изменённого Playwright-теста и `git diff --check` | Успешно |

Команда полного backend-прогона из корня (префикс MSYS нужен именно Git Bash):

```sh
MSYS_NO_PATHCONV=1 docker compose -p alfa-saveliy-docker-qa exec -T web pytest -c /app/pyproject.toml -p no:cacheprovider
```

Проверка кнопки независимо от LLM, из `frontend/`:

```sh
E2E_BASE_URL=http://127.0.0.1:8080 E2E_ASSISTANT_ENABLED=true npx playwright test tests/e2e/assistant.spec.ts --project=chromium --grep @assistant-ui --trace=off
```

Требуется действующий `DEMO_PASSWORD` проверяемого стенда в окружении. Trace отключён, чтобы не сохранять сетевые данные входа. Не коммитить browser artifacts и cookies.

## Настоящая модель и границы доказательств

- Из backend-контейнера доступен `host.docker.internal:11434`.
- На хосте уже была установлена `qwen2.5:7b-instruct-q4_0`; скачивание другой модели и платные API не потребовались.
- Выполнен отдельный настоящий вызов `assistant.llm.chat` с синтетическим русскоязычным вопросом. Транспорт `primary` вернул непустой текст. `ollama ps` подтвердил загруженную Qwen на GPU.
- Браузерный сценарий «окно, сообщение и история» работал с настоящим backend и настроенной локальной моделью, без перехвата модельных ответов.
- Сценарий предложения черновика использует явно подменённый ответ API; это проверка UI и подтверждения, а не качества извлечения полей настоящей Qwen. Проверка низкого окна подменяет список истории для воспроизводимого скролла.
- Успешные smoke/E2E не являются исчерпывающей оценкой качества модели или доказательством соответствия всем требованиям исходного задания. Firefox и WebKit в этом прогоне не запускались.

После проверки временные QA-контейнеры и сеть удалены без `--volumes`. Основной Compose-проект продолжает работать с включённой кнопкой. Инструкция диагностики добавлена в [frontend.md](frontend.md#если-кнопка-савелия-не-отображается-в-docker).
