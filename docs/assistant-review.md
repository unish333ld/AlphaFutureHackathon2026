# Ревью и QA Савелия — 25.10.2026

## Область проверки

Проверена ветка `feat/ai-assistant` на `4270d9e`, задание владельца из `promt.txt` и план `saveliy-redesign-plan.md`. Название `feat/ai-assistent` из сообщения не совпадало с фактической remote-веткой. База интеграции — `main` на `89153b7`. Репозиторий был чистым до начала; секреты и пользовательская демо-БД не изменялись. Проверка следовала alfa-credit-build/guardrails/frontend: сохранить кредитный процесс, минимизировать данные, ограничить полномочия модели и подтвердить перенос в форму.

Основа работы коллеги полезна: отдельный модуль Django, серверные read-only инструменты, session/CSRF, конфигурируемый транспорт, история и feature flags. До исправлений слияние было небезопасно: проверки ответа и переноса формы не обеспечивали требования задания. Ни успешный HTTP-ответ модели, ни скриншот окна не доказывали корректность всего помощника.

## Воспроизведение

Основной запуск/настройка реальной модели: [assistant.md](assistant.md). Для изолированной QA, из корня:

```sh
.venv/bin/python scripts/assistant_test_provider.py --test-provider
# В другом терминале, с локальным .env без секретов в Git:
WEB_PORT=18002 FRONTEND_PORT=18080 VITE_AI_ASSISTANT_ENABLED=true \
AI_ENABLED=true AI_USER_RATE=300/min LLM_PROVIDER=compatible \
LLM_BASE_URL=http://host.docker.internal:19001/v1 LLM_MODEL=qa-test-double \
docker compose -p alfa-ai-review up --build -d --wait --wait-timeout 180
```

Добавьте тестового `e2e-specialist` командой из [frontend.md](frontend.md), заменив имя Compose-проекта на `alfa-ai-review`. Тестовый провайдер нельзя выдавать за работающую LLM и нельзя использовать на продуктовом демо. Из `frontend/`:

```sh
E2E_BASE_URL=http://127.0.0.1:18080 E2E_ASSISTANT_ENABLED=true \
npx playwright test --project=chromium --trace=off
```

Следующие движки запускайте последовательно после завершения окна квоты. Firefox Linux — команда из frontend.md с контейнером `alfa-ai-review-frontend-1`. Не публикуйте auth state/traces/screenshots с данными сессии; артефакты игнорируются Git.

## Оставшиеся ограничения

Настоящая модель в текущем окружении недоступна: Ollama endpoint не отвечает, внешняя конфигурация не предоставлена. Поддержка transport/tools/JSON-schema проверена тестовым провайдером, качество конкретного Qwen-тега и извлечение реальной LLM не подтверждены. Перед демонстрацией необходим отдельный живой прогон и фиксация digest модели. Никакие подписки/платные аккаунты не создавались. Старые сообщения с прежним непроверенным fact envelope показываются как архивные без переноса полей; исходные записи не переписываются (отдельный regression-тест).

Объяснения намеренно ограничены серверным словарём, извлечение параметров консервативно; произвольный финансовый консультант не заявляется. Retention физически очищается при запуске и отдельной командой; непрерывному стенду нужен ежедневный запуск команды оператором. Тексты могут передаваться выбранному провайдеру, поэтому только синтетика; гарантированного автоматического обезличивания нет. Прогноз денежных потоков и стресс-тесты — отдельный следующий этап, OCR и банковская ИИ-сводка вне задачи. Покрытие и зелёные тесты не доказывают отсутствие любых будущих дефектов.
