# Помощник по кредиту: подключение и ограничения

Помощник реализован внутри Django: собственные диалоги, read-only инструменты, OpenAI-совместимый транспорт и панель React. Основной кредитный путь работает без модели. Источник контракта — `docs/openapi.yaml`; схема генерируется из backend.

## Включение

По умолчанию оба флага выключены. Для обычного запуска без ИИ достаточно README. Для подключения модели задайте в локальном `.env`:

```dotenv
VITE_AI_ASSISTANT_ENABLED=true
AI_ENABLED=true
LLM_PROVIDER=openrouter
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=nvidia/nemotron-3-super-120b-a12b:free
LLM_API_KEY=
OPENROUTER_API_KEY=
LLM_OPENROUTER_FREE_ONLY=true
LLM_LOCAL_FALLBACK_BASE_URL=http://host.docker.internal:11434/v1
LLM_LOCAL_FALLBACK_MODEL=qwen3:4b-instruct-2507-q4_K_M
LLM_TIMEOUT_SECONDS=25
LLM_TOTAL_TIMEOUT_SECONDS=75
LLM_MAX_CONTEXT_CHARS=16000
```

Затем выполните `docker compose up --build -d --wait`. Используйте то же имя Compose-проекта и порты, что при предыдущем запуске. Frontend-флаг встраивается при сборке; одного restart недостаточно. Backend-флаг проверяется независимо от наличия кнопки. В кабинете специалиста помощника нет.

OpenRouter — приоритетный маршрут. Даже бесплатным моделям нужен ключ аккаунта: создайте его на [странице ключей](https://openrouter.ai/settings/keys), сохраните `OPENROUTER_API_KEY` в корневой `.env`, затем пересоздайте backend. `LLM_API_KEY`, если заполнен, имеет приоритет. Ключ не передаётся в frontend. Если ключа нет, cloud-запрос не отправляется и используется локальная модель. Без рабочего ключа и без запущенного резерва ответить невозможно.

Для Apple Silicon установите Ollama (`brew install ollama`), запустите `sh scripts/serve_local_llm.sh`, затем в другом терминале `ollama pull qwen3:4b-instruct-2507-q4_K_M`. Скрипт задаёт loopback 11434, 8192 токена контекста, один параллельный запрос/одну загруженную модель, KV q8 и выгрузку через две минуты простоя; cloud Ollama выключен. Веса (~2,5 ГБ) лежат в `~/Library/Application Support/AlfaCredit/ollama-models`, отдельно от репозитория. `OLLAMA_BIN` и `ALFA_CREDIT_LLM_DIR` позволяют изменить путь программы и весов. На других ОС установите официальный Ollama и задайте те же ограничения при `ollama serve`.

На машине владельца установлен пользовательский LaunchAgent `dev.alfa-credit.ollama`: запускает Ollama после входа в macOS. Данные хранятся в Application Support, поскольку фоновый процесс macOS не может читать Desktop без отдельного разрешения. Настройки приватности системы не менялись. Остановка: `launchctl bootout gui/$(id -u)/dev.alfa-credit.ollama`; повторный запуск: `launchctl bootstrap gui/$(id -u) "$HOME/Library/LaunchAgents/dev.alfa-credit.ollama.plist"`. Лог — `~/Library/Application Support/AlfaCredit/ollama.log`, без промптов и API-ключей. Проверка загрузки — `ollama ps`; выгрузить модель немедленно — `ollama stop qwen3:4b-instruct-2507-q4_K_M`.

Для нативного Django адрес резерва — `http://127.0.0.1:11434/v1`. Docker Desktop обращается к хосту через `host.docker.internal`; на Linux настройте доступный адрес хоста. Для полностью локального режима укажите `LLM_PROVIDER=compatible`, `LLM_BASE_URL=http://host.docker.internal:11434/v1`, `LLM_MODEL=qwen3:4b-instruct-2507-q4_K_M`. Порт модели слушает только loopback.

Локальная модель — [Qwen/Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), [Apache-2.0](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/blob/main/LICENSE), Ollama `qwen3:4b-instruct-2507-q4_K_M`, digest `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`. На Apple M2 реально проверены native tool calling и строгий JSON через `/v1/chat/completions`, в том числе из Django-контейнера. `ollama ps` показал 100% GPU, 3,2 ГБ и контекст 8192. Это не обещание качества любого диалога.

Cloud-кандидат — [NVIDIA Nemotron 3 Super 120B A12B FP8](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-FP8), [NVIDIA Nemotron Open Model License](https://www.nvidia.com/en-us/agreements/enterprise-software/nvidia-nemotron-open-model-license/), slug `nvidia/nemotron-3-super-120b-a12b:free`. Каталог OpenRouter проверен 25.10.2026: нулевая цена, `tools`, `tool_choice`, `response_format`, `structured_outputs`. Авторизованный вызов endpoint не выполнен: ключ не предоставлен. Бесплатный endpoint может логировать входы; передавать только синтетику. Лицензии и источники — [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

URL, ключ и модель заменяются без кода. Совместимый endpoint должен поддерживать `/chat/completions`, function tools и `response_format: json_schema`; [Ollama документирует structured outputs](https://docs.ollama.com/capabilities/structured-outputs) и [tool calling](https://docs.ollama.com/capabilities/tool-calling), но это не доказывает качество конкретного тега. Проводите отдельный живой прогон. Для внешнего endpoint проверяйте точную модель, лицензию, поддержку функций, стоимость и правила обработки запросов. Обязательной платной зависимости нет. Режим `LLM_PROVIDER=openrouter` сохраняет явный список `LLM_MODEL`/`LLM_FALLBACK_MODELS`; произвольный авто-маршрутизатор использовать не следует. Необязательный локальный fallback задаётся `LLM_LOCAL_FALLBACK_BASE_URL` и `LLM_LOCAL_FALLBACK_MODEL`. При 401/402/403/429 cloud-маршрут ставится на паузу на пять минут в данном worker. Это не автоматический повтор кредитного действия.

## Текущий сценарий и доверие

Панель показывает один актуальный вопрос или результат. История сообщений остаётся на сервере для ограниченного контекста модели и аудита, но не загружается в интерфейс. Режим шага приходит явно: `choice`, `input`, `waiting`, `result` или `error`. Текст ответа модели не определяет тип элемента ввода.

- `POST /api/v1/assistant/conversations/current/` с `company_id` и необязательным `application_id` создаёт или восстанавливает сценарий в доступной компании.
- `GET /api/v1/assistant/conversations/{id}/step/` возвращает текущий шаг. После потерянного ответа клиент сначала вызывает этот GET.
- `POST /api/v1/assistant/conversations/{id}/step/` принимает `expected_version`, `step_id`, `request_id` и один из `action_id` или `text`. На шаге выбора текст запрещён, на шаге ввода разрешён только текст. Старый шаг и произвольный action_id получают 409.
- Повтор того же `request_id` с тем же содержимым возвращает текущее состояние без повторного действия. Иное содержимое с прежним ID получает 409. HTTP 200 с `mode=error` означает сохранённую техническую ошибку, а не готовый ответ.

Все запросы используют session cookie и CSRF. Сервер проверяет пользователя, активное членство компании и связь заявки. Версия сценария не равна `lock_version` заявки. При изменении заявки во время ответа сервер не сохраняет устаревшие данные. Ожидающий шаг завершается ошибкой по ограниченному времени; поздний ответ не может восстановить старое состояние.

Сценарий помогает выбрать активный продукт, ввести сумму и срок, получить предварительный расчёт или подготовить поля для обычной формы. Сумма и срок проверяются по границам продукта. Вопрос свободным текстом получает ответ через выбранную модель. Модель выбирает объяснения из серверного словаря и может вызвать только читающие инструменты: каталог, профиль компании, статус заявки, предварительный расчёт и предложение полей. Она не отправляет заявку, не определяет решение, ставку, подпись или выдачу. Финансовые показатели помощник не заполняет.

Предложение полей переносится в форму после отдельного подтверждения. Перед переносом проверяются актуальность шага, доступный каталог, версия заявки и неизменность открытой формы. При reload без снимка формы существующий ввод не перезаписывается. В Web Storage не сохраняются сообщения, финансовые payload и код подтверждения.

Прежние `/assistant/conversations/` и `messages/` сохранены для совместимости и серверной истории; новая панель не вызывает список, удаление и постраничную историю. Обычный POST сообщения к пошаговому диалогу возвращает 409. Старые диалоги не преобразуются и не удаляются.

## Ошибки и ресурсы

400 — формат или недопустимое значение поля; 403 — сессия, права или CSRF; 404 — недоступная компания, заявка или диалог; 409 — старый шаг, занятый запрос или неверное действие; 429 — лимит с `Retry-After`; 503 — отключённый помощник или общая недоступность. Сбой модели внутри пошагового запроса возвращает 200 с `mode=error` и сохранённым вводом. При 409 или потере ответа панель читает текущий шаг, не отправляя действие повторно. Если чтение тоже не удалось, остаётся ручная кнопка проверки. Основная заявка доступна без помощника.

| Настройка | Значение по умолчанию / границы |
|---|---|
| AI_MAX_MESSAGE_LENGTH | 2000 символов, 100–4000; UI ограничен 2000 |
| AI_USER_RATE | 10/min, единая фиксированная квота пользователя в PostgreSQL между workers |
| LLM_TIMEOUT_SECONDS | 40 с, 1–40 на сетевой вызов |
| LLM_TOTAL_TIMEOUT_SECONDS | 70 с, 1–75 на последовательность вызовов |
| LLM_MAX_OUTPUT_TOKENS | 768, 128–2048 |
| LLM_MAX_CONTEXT_CHARS | 20000, 4000–40000; включая инструкции, историю и tool results |
| Инструменты | максимум два вызова за ответ; следующие tool calls не исполняются |
| История в контексте модели | максимум восемь предыдущих сообщений |
| HTTP-ответ провайдера | максимум 256 KiB |
| AI_HISTORY_DAYS | 7 дней неактивности, 1–30 |

Nginx ждёт 85 с, Gunicorn — 90 с, браузер — 90 с. Сетевые таймауты и размер ответа ограничены сервером; закрытие панели не обещает отмену вычисления у провайдера. Перенаправления провайдера запрещены, чтобы ключ не ушёл на другой URL. Диагностика транспорта содержит request ID, статус и длительность, без промптов/сообщений/ключей и без внешней трассировки.

Gunicorn использует два процесса по четыре потока. В каждом процессе разрешён только один одновременный сетевой вызов LLM; остальные попытки получают 503 без очереди. Это оставляет потоки для кредитного API даже при медленной модели. Это ограничение конкуренции, отдельное от общей пользовательской квоты PostgreSQL; при масштабировании число модельных слотов растёт с числом workers.

История хранится в PostgreSQL, принадлежность проверяется по пользователю и компании. Истёкшие диалоги скрыты. Команда `python manage.py purge_assistant_history` удаляет просроченные записи и запускается при старте; на постоянно работающем стенде её следует запускать ежедневно. API удаления собственного старого диалога сохранён для совместимости, но кнопки удаления в панели нет. Срок относится к активной БД, не обещает удаления из резервных копий. Таблица квот не хранит содержание переписки.

Панель предупреждает не вводить реальные персональные и банковские данные. Автоматическое обезличивание не заявляется. Для демо используйте только синтетику: сообщения могут передаваться выбранному внешнему провайдеру.

## Проверка

Живой сценарий: «Подготовить заявку» → выбор продукта → сумма → срок → проверка предложения → явный перенос в форму → ручной ввод финансовых показателей. Отдельно выбрать «Задать вопрос» и проверить настоящий ответ модели. На карточке выбрать помощь по заявке и сравнить результат с карточкой. Проверить сбой провайдера и обычный кредитный путь при `AI_ENABLED=false`.

Тесты разделены: pytest подменяет модель и проверяет права/схемы/инварианты. Playwright проходит настоящий Django API в изолированной QA-среде: либо с реальной настроенной моделью (`E2E_LIVE_MODEL=true`), либо с отдельно запущенным `scripts/assistant_test_provider.py --test-provider`. Второй режим — явно обозначенный HTTP test double, не LLM, не доказательство её качества и не production fallback. Запрещено подключать его к демонстрационному стенду как настоящую модель. Ошибки сети/409/429/503 в browser-тестах внедряются отдельно и не выдаются за ответы модели.
