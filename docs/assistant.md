# Савелий: подключение и ограничения

Помощник реализован внутри Django: собственные диалоги, read-only инструменты, OpenAI-совместимый транспорт и панель React. Основной кредитный путь работает без модели. Источник контракта — `docs/openapi.yaml`; схема генерируется из backend.

## Включение

По умолчанию оба флага выключены. Для обычного запуска без ИИ достаточно README. Для подключения модели задайте в локальном `.env`:

```dotenv
VITE_AI_ASSISTANT_ENABLED=true
AI_ENABLED=true
LLM_PROVIDER=compatible
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_MODEL=qwen2.5:7b-instruct-q4_0
LLM_API_KEY=
```

Затем выполните `docker compose up --build -d --wait`. Используйте то же имя Compose-проекта и порты, что при предыдущем запуске. Frontend-флаг встраивается при сборке; одного restart недостаточно. Backend-флаг проверяется независимо от наличия кнопки. В кабинете специалиста помощника нет.

Для отдельного локального запуска установите Ollama, выполните `ollama serve`, затем в другом терминале `ollama pull qwen2.5:7b-instruct-q4_0`. Модель загружается отдельно и требует нескольких гигабайт диска и памяти; скорость зависит от оборудования. Для нативного Django используйте `http://127.0.0.1:11434/v1`. Docker Desktop обращается к хосту через `host.docker.internal`; на Linux настройте доступный адрес хоста. Порт Ollama не требуется публиковать в интернет.

Выбранный кандидат — [Qwen/Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct), открытые веса, [Apache-2.0](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct/blob/main/LICENSE). Квантованный тег Ollama указан выше; точный digest установленной модели фиксируйте при живой проверке. Лицензия исходной модели проверена 25.10.2026. В этой сессии настоящая модель не запускалась: локальный endpoint недоступен, ключ внешнего провайдера не предоставлен.

URL, ключ и модель заменяются без кода. Совместимый endpoint должен поддерживать `/chat/completions`, function tools и `response_format: json_schema`; [Ollama документирует structured outputs](https://docs.ollama.com/capabilities/structured-outputs) и [tool calling](https://docs.ollama.com/capabilities/tool-calling), но это не доказывает качество конкретного тега. Проводите отдельный живой прогон. Для внешнего endpoint проверяйте точную модель, лицензию, поддержку функций, стоимость и правила обработки запросов. Обязательной платной зависимости нет. Режим `LLM_PROVIDER=openrouter` сохраняет явный список `LLM_MODEL`/`LLM_FALLBACK_MODELS`; произвольный авто-маршрутизатор использовать не следует. Необязательный локальный fallback задаётся `LLM_LOCAL_FALLBACK_BASE_URL` и `LLM_LOCAL_FALLBACK_MODEL`. При 401/402/403/429 cloud-маршрут ставится на паузу на пять минут в данном worker. Это не автоматический повтор кредитного действия.

## Контракт и доверие

- `POST assistant/conversations/`: доступная `company_id`, необязательная принадлежащая ей `application_id`.
- `GET assistant/conversations/`, `GET assistant/conversations/{id}/`: только собственная история при действующем членстве.
- `GET assistant/conversations/{id}/messages/`: объект пагинации `count/next/previous/results`, 25 сообщений.
- `POST assistant/conversations/{id}/messages/`: `text` и `expected_version`; session cookie и CSRF обязательны.
- `DELETE assistant/conversations/{id}/`: удаление своего диалога и всех сообщений, 204; CSRF обязателен.

Все пути начинаются с `/api/v1/`. Запросы не принимают `user_id`, роль, system/tool-сообщения и произвольную историю. Права проверяются при чтении и повторно после сетевого ответа. Диалог блокируется при сохранении: из конкурирующих ответов одной версии сохраняется только одна пара сообщений. Если заявка изменилась во время ответа, сервер возвращает 409 без сохранения устаревших фактов. Истечение предложения сверяется серверным сервисом, включая время обработки ответа.

Ответ содержит `conversation_id`, новую `version`, `model_status` и `message`. В сообщении: `reply_type=answer/missing_information/draft_suggestion`, `content`, `questions`, `facts`, `suggested_draft`, `application_id`, `application_version`. Для обычного сообщения пользователя последние поля пустые/null по схеме. `model_status=degraded` означает, что модель не завершила объяснение после успешного чтения: показаны только серверные факты. Не выдавать его за полноценный ответ модели.

Ответы из ранней версии с непроверенным форматом facts показываются как архивные (degraded), без переноса старых полей; исходная запись в БД не переписывается. Для получения данных нужно задать новый вопрос. Любая сохранённая переписка — история, не подтверждение текущего состояния заявки.

В этом релизе модель выбирает объяснение из небольшого серверного словаря и ограниченные инструменты. Свободный текст модели не публикуется: это сознательная граница, чтобы нельзя было выдумать одобрение, ставку или обязательные документы словами. JSON проверяется закрытой схемой; идентификаторы источников сверяются с полученными фактами. После неверного финального JSON допускается одна попытка исправления, затем 503. Интерфейс показывает суммы, предложения и причины отдельно из серверных блоков. `fact_1/fact_2` действуют внутри одного ответа, это не внешние ссылки и не постоянные идентификаторы документов.

Инструменты: профиль выбранной компании без ИНН/контактов; активные продукты; статус/ревизия/разрешённые клиентские действия/сохранённые причины и предложение; серверный предварительный расчёт; предложение полей черновика. Банковские оценки и raw checks клиенту не передаются. Инструментов изменения заявки, решения, подписания, назначения и выдачи нет.

Черновик и расчёт требуют явных значений суммы/срока из пользовательских сообщений и выбранного активного продукта. Поддержаны обычные рублёвые формулировки с цифрами, тыс./млн, миллион/два миллиона, год/полгода и месяцы. Синонимы «Оборотные», «ну средства оборотные» разрешаются через активный каталог; подтверждённый продукт сохраняется отдельно. Диапазоны, альтернативы и иностранная валюта требуют уточнения. Другие числительные могут потребовать повторного ввода цифрами. Выручка/расходы не используются как запрошенная сумма. Финансовые показатели помощник не заполняет.

Перед переносом пользователь видит «было → станет». У открытой формы сверяется снимок всех полей и версии заявки, у сохранённого ответа — версия заявки и свежий каталог. Изменившаяся форма не перезаписывается. Историческое предложение нельзя применять поверх формы без нового вопроса. Новая форма получает разрешённые поля через память React, без Web Storage и состояния URL/history. Сохранение и отправка выполняются штатным API.

## Ошибки и ресурсы

400 — поля/схема запроса; 403 — сессия/роль/CSRF; 404 — недоступный диалог/компания/заявка; 409 — версия диалога или заявки; 429 — квота, `Retry-After`; 503 — AI выключен, провайдер недоступен, неверный ответ или чрезмерный контекст. При 409/сетевой неопределённости интерфейс сверяет историю, сохраняет ввод и не отправляет сообщение повторно автоматически. Если успешная пара сообщений найдена, сообщает об этом явно. При 429 кнопка ждёт указанную паузу.

| Настройка | Значение по умолчанию / границы |
|---|---|
| AI_MAX_MESSAGE_LENGTH | 2000 символов, 100–4000; UI ограничен 2000 |
| AI_USER_RATE | 10/min, единая фиксированная квота пользователя в PostgreSQL между workers |
| LLM_TIMEOUT_SECONDS | 40 с, 1–40 на сетевой вызов |
| LLM_TOTAL_TIMEOUT_SECONDS | 70 с, 1–75 на последовательность вызовов |
| LLM_MAX_OUTPUT_TOKENS | 768, 128–2048 |
| LLM_MAX_CONTEXT_CHARS | 20000, 4000–40000; включая инструкции, историю и tool results |
| Инструменты | максимум два вызова за ответ; следующие tool calls не исполняются |
| История в контексте модели | максимум восемь предыдущих сообщений |
| HTTP-ответ провайдера | максимум 256 KiB |
| AI_HISTORY_DAYS | 7 дней неактивности, 1–30 |

Nginx ждёт 85 с, Gunicorn — 90 с, браузер — 90 с. Сетевые таймауты и размер ответа ограничены сервером; закрытие панели не обещает отмену вычисления у провайдера. Перенаправления провайдера запрещены, чтобы ключ не ушёл на другой URL. Диагностика транспорта содержит request ID, статус и длительность, без промптов/сообщений/ключей и без внешней трассировки.

Gunicorn использует два процесса по четыре потока. В каждом процессе разрешён только один одновременный сетевой вызов LLM; остальные попытки получают 503 без очереди. Это оставляет потоки для кредитного API даже при медленной модели. Это ограничение конкуренции, отдельное от общей пользовательской квоты PostgreSQL; при масштабировании число модельных слотов растёт с числом workers.

История хранится в PostgreSQL, принадлежность проверяется по пользователю и компании. Истёкшие диалоги скрыты. Команда `python manage.py purge_assistant_history` физически удаляет просроченные диалоги и сообщения, выполняется при старте; для непрерывно работающего стенда запускайте её ежедневно планировщиком оператора. Пользователь может удалить доступный диалог сразу. Срок относится к активной БД, не обещает удаления из резервных копий. Техническая таблица квот не хранит содержание переписки.

Панель предупреждает не вводить реальные персональные и банковские данные. Автоматическое обезличивание не заявляется. Для демо используйте только синтетику: сообщения могут передаваться выбранному внешнему провайдеру.

## Проверка

Живой сценарий: вопрос о полях → «Нужен миллион на закупку товара на год» → выбор «Оборотные» → проверка предложения → явный перенос в форму → ручной ввод фактических показателей. На карточке спросить о статусе/решении и сверить блок с самой карточкой. Проверить отказ провайдера и обычный кредитный путь при `AI_ENABLED=false`.

Тесты разделены: pytest подменяет модель и проверяет права/схемы/инварианты; Playwright проходит настоящий Django API с отдельно запущенным `scripts/assistant_test_provider.py --test-provider` только в изолированной QA-среде. Это явно обозначенный HTTP test double, не LLM, не доказательство её качества и не production fallback. Запрещено подключать его к демонстрационному стенду как настоящую модель.

Результаты текущего ревью и точные выполненные команды: [assistant-review.md](assistant-review.md). Прогноз денежных потоков, OCR и ИИ-сводка сотрудника не входят в эту задачу.
