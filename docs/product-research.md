Последующее развитие 26.10.2026: динамический PDF, кодовое демо-подтверждение, отдельная копия и выдача интегрированы в API **1.3.0**. Актуальная проверка — [qa-product-research.md](qa-product-research.md), протокол — [agreements.md](agreements.md). Ниже сохранена история этапа API 1.2, а не текущий размер тестового набора.

Существующие следующие действия, уточнения новой ревизией и история сохранены. Конкретные баллы конкурса и рост конверсии не обещаются.

## Числа и происхождение

Публичный ориентир — [разовый кредит Альфа-Банка без залога](https://alfabank.ru/sme/profits/businesscredit/). Поисковая копия официальной страницы 25.10.2026 подтвердила диапазон 300 тыс.–30 млн ₽, 12–60 месяцев, ставку **от** 23,5%, деятельность от девяти месяцев. Прямой запрос дал timeout; тариф с датой вступления в силу не получен (`effective_from=null`, `access_mode=search_index`). Это справка, не действующая оферта. Минимумы со скидками не применяются: цена платных услуг индивидуальна.

| Данные | Тип и применение |
|---|---|
| Публичные пределы/минимум ставки | `public_product`: источник/дата/сегмент доступны в форме и каталоге; не персональные условия |
| Ставка 27%, отсутствие комиссий и подключённых услуг, месячная модель | `demo_assumption`: исполнимые учебные условия двух продуктов по целям |
| Платёж/проценты/итог/разница условий | `derived`: серверный расчёт из конкретных входов и округлённого графика |
| Финансовые поля клиента | Синтетические месячные сведения; неизвестное остаётся null, ноль — явное введённое значение |
| Результаты проверок ниже | `measured_project`: качество программного прототипа, не бизнес-конверсия/качество банковской модели |

Деньги — RUB до копейки, сроки — месяцы, ставка — проценты годовых. Поручительства, территория обслуживания и полный набор требований банка не моделируются. Выручка не называется прибылью. Расходы включают операционные затраты/налоги, долговой сервис указывается отдельно за тот же месяц.

Сохранены `demo-score-1` / `demo-policy-1`: C = выручка − расходы, B = max(0, 0,50 × C − существующий платёж). Долг не вычитается дважды. Это допущения проекта; реальный ПКР 1–999/PD и внутренние модели Альфы не рассчитываются.

Проверенный пример: C=180000, долг 30000 → B=60000 ₽. Запрос 1500000 ₽ на 24 месяца при 27% → 81570,34 ₽; текущий сервер предлагает 1103342,17 ₽ и 60000 ₽/мес. Иллюстративный скрипт навыка дополнительно округляет тело вниз до 10000 ₽ (1100000 ₽ / 59818,25 ₽). Сервер сохранил существующее округление лимита до копейки; исходный запрос не переписывается.

## Что получает пользователь

| Фича | Результат и проверяемое условие |
|---|---|
| F01 | К зачислению, проценты, итог возврата и расходы видны сразу; сборы и первый/максимальный/последний платёж раскрываются отдельно. График сходится до копейки |
| F02 | «Запрашивали → предлагаем»: сумма, срок, ставка, платёж, итог по рассмотренной revision и фактическому Offer. Новая цена каталога не меняет старое сравнение |
| F03 | Недостающие месячные показатели видны в чек-листе; кнопка переводит фокус в нужное поле. Другие значения сохраняются, ноль долга отличается от пропуска |
| F05 | Паспорт стоимости доступен при принятии и условной подписи, сохраняется в хэшируемом договоре и остаётся тем же после выдачи |

Гипотезы пользы и будущие метрики, **ещё не измеренные на предпринимателях**:

| Проблема → действие → ожидаемый результат | Метрика пользовательской проверки |
|---|---|
| F01: месячного платежа недостаточно → открыть стоимость → назвать сумму к зачислению и возврату | Правильные ответы и время поиска обеих сумм |
| F02: непонятно, что изменил банк → сравнить две колонки → объяснить уменьшение суммы и платежа | Число правильно найденных изменений и время сравнения |
| F03: неизвестно, чего не хватает → нажать конкретный показатель → исправить поле без потери остальных | Доля завершённых исправлений и ошибки ввода |
| F05: условия легко пропустить → прочитать паспорт в подтверждении → осознанно принять/подписать те же условия | Правильное понимание расходов перед подтверждением; расхождения условий должны отсутствовать |

Данные/API перечислены ниже: калькулятор для F01, Offer.comparison для F02, Application.readiness для F03, Offer/Agreement.cost_breakdown и terms_snapshot для F05. Это проверяемые гипотезы, не доказанный рост конверсии.

Заполненность не является процентом одобрения. Недостаточные финансовые данные по прежнему можно отправить: backend запросит уточнение. Подсказки не заменяют `available_actions` и проверку в транзакции. Роли/назначения/lock_version/подтверждение подписи/Idempotency-Key сохранены. Проверки, подпись и выдача моделируемые.

`CostBreakdown.is_complete` относится только к поддерживаемой учебной модели. Неизвестные или неподдерживаемые сборы дают null для итога/комиссий/суммы к зачислению; показывается известная сумма платежей. Неизвестные банковские услуги не заменяются нулём. Юридическая ПСК и прогноз бизнеса не рассчитываются.

## API 1.2.0 и данные

- Product дополнен nullable `catalog_reference`: источник, даты, единицы, публичные пределы/ограничения.
- `POST /api/v1/calculator/payment/`: product + amount + term_months берут ставку/пределы с сервера. Альтернативный самостоятельный режим annual_rate сохранён. Одновременно product/annual_rate запрещены. Ответ дополнен annual_rate, rate_source, catalog_version, cost_breakdown; заявка/решение не создаются.
- Application дополнен `readiness` текущей revision/lock_version: can_submit/reason_code, конкретные missing/ready-поля. Только в доступной карточке.
- Offer дополнен `cost_breakdown` / `comparison` из зафиксированной revision/Offer, без живого тарифа; сравнение содержит source_revision_id.
- Agreement дополнен cost_breakdown; новые terms_snapshot фиксируют стоимость/catalog_version. Для старого договора стоимость читается из его прежнего графика: JSON/hash в БД не переписываются. Новые ключи снимков опциональны ради старых записей.

OpenAPI обновлена с валидацией, TS-типы сгенерированы из неё. График v1, кредитные состояния и маршруты действий сохранены. Новый endpoint/микросервис не потребовался.

## Миграции и запуск

`products.0002_add_catalog_reference` добавляет nullable JSON. `products.0003_research_catalog` обновляет только активные встроенные seed-продукты с исходными UUID/кодом/версией и нетронутыми финансовыми параметрами. Пользовательские ставки/версии и отключённые продукты пропускаются. Старые ревизии/предложения/договоры не пересчитываются. Повтор безопасен; обратный data migration не откатывает цены, чтобы не повредить новые заявки.

На чистой БД seeds сразу создают новый каталог. Пароли существующих пользователей не сбрасываются. Организатор запускает проект по [README](../README.md): создать локальный `.env` из примера, задать Django key/пароли и выполнить `docker compose up --build -d --wait --wait-timeout 180`. Миграции/seeds выполняет entrypoint. Этим четырём функциям LLM и её ключ не нужны.

На машине владельца использовать прежнее имя проекта `alfa-credit-demo`, frontend 8080 / backend 18000, чтобы сохранить существующий volume. Новые цены записывать с новой rules_version: новые заявки фиксируют их при отправке, старые сделки остаются со своим снимком.
