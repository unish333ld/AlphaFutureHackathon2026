# Савелий: подключение настоящей модели — 25.10.2026

Продолжение [ревью ветки коллеги](assistant-review.md), не замена исторических результатов. Цель — работающий помощник без ключей коллеги, OpenRouter в приоритете и локальный бесплатный резерв. Применены alfa-credit-build, alfa-credit-guardrails и alfa-credit-frontend; разрешение владельца развивает визуальную заготовку в настоящую необязательную интеграцию.

## Что работает

На машине владельца основной Compose-проект `alfa-credit-demo` запущен с `AI_ENABLED=true` и собранным `VITE_AI_ASSISTANT_ENABLED=true`. Интерфейс — http://localhost:8080, Django/Swagger — http://localhost:18000/api/docs/. Компания и кредитные данные существующей БД сохранены; тестовые кредитные изменения выполнялись в отдельном проекте `alfa-ai-live`.

Приоритетный маршрут настроен на OpenRouter, `nvidia/nemotron-3-super-120b-a12b:free`. Ключа аккаунта нет, поэтому сейчас реальные ответы обрабатывает **локальный Ollama**, `qwen3:4b-instruct-2507-q4_K_M`. Это настоящая модель, не HTTP test double. Успех локального резерва не означает успешное подключение OpenRouter. Для cloud нужен собственный `OPENROUTER_API_KEY` в игнорируемом корневом `.env`, затем `docker compose -p alfa-credit-demo up -d --force-recreate web frontend`. Ключ в чат/репозиторий/`VITE_*` передавать нельзя; чужой ключ не требуется. После настройки выполнить `check_assistant --live` и посмотреть фактический маршрут.

Локальная модель: Qwen3-4B-Instruct-2507, Apache-2.0, digest `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`; происхождение и лицензии — [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). OpenRouter-каталог и лицензия NVIDIA проверены, но авторизованный cloud-вызов без ключа не выполнялся.

## Исправления после живых диалогов

- Для совместимых chat templates политика и проверенный серверный контекст передаются одним system message. Модель видит выбранный продукт, подтверждённые параметры и наличие выбранной заявки. Текст вопроса и история остаются сообщениями пользователя, не инструкциями сервера.
- Уточнена маршрутизация ограниченных инструментов: каталог до выбора продукта, предложение полей после подтверждения суммы/срока/продукта, отдельный серверный расчёт платежа, статус только выбранной заявки. Известные параметры не спрашиваются повторно. Нейтральная цель при отсутствии явной цели показывается только для проверки в обычной форме, не сохраняется автоматически.
- Убрано дублирование кнопок продукта при одновременном серверном каталоге и вопросе о выборе; вопрос о финансовых показателях больше не вызывает лишний выбор продукта.
- Диагностика keyboard/focus событий выявила потерю фокуса на границе 1024 px: responsive Core Button менял DOM-узел, Enter попадал в body. Внутри панели выбран стабильный Core ButtonDesktop (адаптивный layout сохранён); регрессионный тест проверяет неизменность узла запуска и фокус на всех ширинах, а не маскирует сбой задержкой/повтором.
- Исправлен разбор «рассчитай предварительный платёж: миллион рублей на 12 месяцев»: запрос расчёта больше не маскирует сумму. Выручка, расходы и платежи по существующим обязательствам по-прежнему исключаются из суммы нового кредита. Добавлены отдельные регрессионные примеры.
- Добавлена безопасная команда `check_assistant [--live]`, алиас `OPENROUTER_API_KEY` только для OpenRouter и защита от платных slugs/ненулевых цен. Реальные browser-тесты имеют отдельный флаг и бюджет ожидания, автоматических повторов значимых действий нет.
- В fault-injection потери ответа `route.fetch` согласован с 90-секундным бюджетом реальной модели (вместо default 10 с), без redirect/retries и только после HTTP 200. Ошибки этой тестовой операции не печатают Cookie/CSRF headers. Диагностический первый Firefox-прогон имел 9 passed / 1 failed из-за этого тестового таймаута; изолированные QA-сессии после диагностики отозваны, основной стенд не затронут.

API-контракт и модели БД не менялись, новых миграций не требуется. Старые свободные ответы модели не возвращались: строгая JSON-схема, серверный словарь, факты/версии/права и read-only allowlist сохранены.

## Правила хакатона и устройство

| Ограничение | Реализация |
|---|---|
| H01/H02 | Только синтетические данные, банковские проверки остаются локальными моками |
| H03/H10 | Без обязательной оплаты/выданных токенов: реальный локальный резерв, cloud `:free`, ценовые пределы ноль |
| H07/H11 | Открытые веса, указанные лицензии/источники/digest, явное разделение модели и test double |
| H08/H09 | Сменяемые URL/ключ/модель, Docker для приложения, инструкция внешнего Ollama без зависимости от коллеги |
| Полномочия | Нет инструментов отправки/решения/подписи/выдачи; перенос полей только после подтверждения |

Ollama установлен нативно через Homebrew, а не моделью в Docker; Metal работает на GPU. Веса ~2,5 ГБ — в `~/Library/Application Support/AlfaCredit/ollama-models`. Пользовательский LaunchAgent `dev.alfa-credit.ollama` поднимает loopback-сервер при входе; контекст 8192, одна модель/один параллельный запрос, очередь два, выгрузка после двух минут простоя. Реально наблюдалось 3,2 ГБ памяти модели и 100% GPU. Это ограничение модели, не всей памяти приложения. Платные аккаунты не создавались, системная защита/разрешения приватности не отключались, сторонние данные не удалялись.

RepoWise установлен как отдельный dev-инструмент в игнорируемой `.deps/repowise-venv`, исключённой из Docker build. Индекс локальный, telemetry выключена, mock embedder/full-text, без платного LLM/embedding и без индексирования `.env`. Использованы context/risk/why и change-review. Анализ отметил размеры/сложность уже существующих assistant-функций и рост `_model_messages`/`_request`; рекомендации тестов были inferred, не доказанной coverage-картой. Это сигнал сопровождения, не доказательство runtime-багов. Большой widget — отдельный кандидат на декомпозицию; срочная конфигурация не сопровождалась широким переписыванием.

При синхронизации Git устранён конфликт устаревшего локального `origin/feat` с актуальным `origin/feat/ai-assistant`: удалён только remote-tracking ref, затем выполнен fetch. Ветки GitHub и коммиты не удалялись; прежний commit остаётся в истории main.

Остановка сервиса/выгрузка модели и подробный запуск — [assistant.md](assistant.md). QA-контейнеры можно остановить `docker compose -p alfa-ai-live down` без `-v`; это сохраняет изолированный volume. Основной проект и его БД не удалять.

## Ограничения

OpenRouter ещё требует собственного ключа и отдельного живого подтверждения: бесплатная квота/поддержка endpoint могут меняться. Контекст/словарь и извлечение параметров намеренно ограничены; успешные сценарии не обещают ответ на любой вопрос. Возможны 503 при занятости модели и 429 квоты, интерфейс сохраняет ввод. История по умолчанию хранится семь дней; ежедневный purge на непрерывном стенде — задача оператора. Реальные Safari/iOS и Chrome/Android не проверялись.

Прогноз денежных потоков и стресс-тесты остаются следующим продуктовым этапом; OCR, распознавание выписок и банковская ИИ-сводка не добавлялись.
