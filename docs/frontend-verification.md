# Проверка frontend — 24.10.2026

Это первичный прогон. Последующий цикл с найденными дефектами, исправлениями и повторными проверками: [qa-auth-verification.md](qa-auth-verification.md).

Реализованы React/Vite frontend и Nginx поверх существующего Django backend. Никаких runtime-моков API, новых серверных технологий, JWT или LLM. В этой frontend-доработке модели и миграции backend не менялись; ранее подготовленные backend-изменения сохранены.

### Сценарии

- Полностью через UI: параметры → проверка/отправка → claim → запрос уточнения → ответ новой ревизией → серверное одобрение → принятие → договор/явная условная подпись → выдача специалистом → перезагрузка с сохранённым результатом. Проверено сохранение суммы с одной копейкой.
- Встречное предложение и отклонение клиентом; отказ; отсутствие показателей; техническая ошибка проверки при HTTP200 и разрешённый retry.
- Пагинация очереди, ввод поиска, фильтры статуса/риска/исполнителя, собственный release. Гонка двух специалистов: один200, другой409; чужое освобождение не показывается, занятую заявку нельзя забрать через UI.
- 409 черновика: введённые данные остаются, выводится серверная версия, новое действие требует явного подтверждения. Чужая компания недоступна.
- Недостаточные полномочия бухгалтера на подпись, 429 с Retry-After, безопасное503 без внутренних подробностей, отсутствие автоматических повторов мутаций.
- Session/CSRF, вход/выход, HttpOnly cookie, запрет POST без CSRF, повторный вход с сохранением ввода, смена пользователя без чужих данных. Отдельная регрессия: запоздалый `/me`, начатый до logout, не возвращает предыдущую учётную запись.
- Потеря ответа выдачи после выполнения сервером: карточка подтверждает результат без второго POST. Потеря до выполнения: намерение переживает reload, явный повтор использует тот же Idempotency-Key. Проверки используют реальную PostgreSQL; лишь потеря ответа и ошибки зависимостей вводятся Playwright fault injection.

### Визуальная и доступная работа

Скриншоты формы и карточки сопоставлены с PNG; сохранены белые панели, светлый фон, красный акцент, композиция клиентской формы и банковского кабинета. Логотип — официальный компонент `@alfalab/icons-logotype`, не текстовая заглушка.

Проверены viewport360,600,768,1024,1280,1440 CSS px в трёх движках; форма перестраивается в одну колонку, очередь — в мобильные карточки. Проверка отсутствия горизонтального скролла всей страницы прошла. График платежей допускает локальный скролл таблицы. На телефоне помощник размещён в потоке, не поверх полей.

Axe WCAG2A/AA/2.1AA не обнаружил нарушений на проверенных главной, очереди, пустом клиентском списке, экранах входа, параметров и проверки заявки. Это не полная ручная сертификация доступности. Проверены Space для checkbox, Escape/возврат фокуса помощнику, предупреждение о несохранённых изменениях. Применён CSS zoom=2 для smoke-проверки reflow; реальный пользовательский browser zoom/assistive technologies отдельно не проверялись.

В Core Select50.38 отсутствовало доступное имя внешнего combobox: небольшой адаптер добавляет aria-label и декоративную стрелку, не меняя внутренние классы/логику библиотеки. Контраст скорректирован поддерживаемыми дизайн-токенами. Для WebKit явно восстанавливается фокус на инициаторе диалога после закрытия.

## Ограничения и предупреждения

- Локальный Firefox на macOS не смог открыть профиль (`Could not find profile folder`), включая попытку с `/private/tmp`. Успешный полный прогон выполнен в Linux-контейнере; macOS Firefox успешным не объявляется. Похожее ограничение описано в [Playwright issue42768](https://github.com/microsoft/playwright/issues/42768). Full Disk Access, настройки или профиль браузера пользователя не менялись.
- Реальные Safari/iOS, Chrome/Android и физические устройства недоступны; WebKit не равнозначен проверке Safari. Публичные HTTPS, нагрузка и реальные банковские интеграции не проверялись.
- Прямые Core Components50.38 поддерживают React18.3.1; транзитивный react-virtual2 имеет устаревший peer16/17. `npm ci` сообщает предупреждение, но проходит без `--force`/`--legacy-peer-deps`. Выбран nativeSelect, виртуализированные списки не используются. Есть upstream deprecation warnings транзитивных пакетов.
- Vite предупреждает о shared JS chunk около719KB (227KB gzip), преимущественно React/Router/Core/RHF/Zod. Предупреждение не подавлялось; дальнейшая оптимизация vendor split возможна отдельно.
- Backend pytest сообщил144 deprecation warnings drf-spectacular/Python3.14 и предупреждение о недоступном pytest-cache для непривилегированного пользователя контейнера. Все344 теста прошли; запуск с root ради кеша не применялся.
- Демо не предусматривает административное переназначение деактивированного специалиста; UI не обходит это. Истечение предложений устанавливает backend при чтении/expire_offers, не локальный таймер.

Все данные синтетические, банковские проверки — моки, подпись и выдача — моделирование. ИИ — только отключаемая панель. **Прогноз денежных потоков и стресс-тесты остаются следующим продуктовым этапом**, исключённым из текущей навигации.

Запуск, тестовые профили, команды и маршруты: [frontend.md](frontend.md). Артефакты Playwright игнорируются Git; `.auth/` и traces могут содержать тестовые cookies, не публиковать их.

После проверок изолированный `alfa-credit-ui-e2e` остановлен без удаления БД/volume. Основной `alfa-credit-demo` оставлен работающим на http://localhost:8080; пароль демо-профилей берётся из локального `.env`. Коммит/push в рамках frontend-задачи не выполнялись.
